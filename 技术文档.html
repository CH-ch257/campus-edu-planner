校园资料AI检索助手 技术文档

1. 项目概述

1.1 项目背景

在校园日常学习与办公中，课程课件、培养方案、考试通知、实验报告等资料散落在班级群、个人U盘、网盘等各处，存在以下典型痛点：

痛点具体表现传统解决方式的局限
资料分散同一门课的课件可能分布在多个群文件、多个同学的U盘中每次找资料需要翻多个渠道，效率极低
查找困难只能靠"文件名记忆"去找，记不清文件名就找不到没有内容级检索能力，无法按语义搜索
版本混乱同一份培养方案被反复修改，群里同时存在多个版本无法区分新旧版本，容易用错过期文件
信息无法问答培养方案里的学分要求、考试通知里的细则需要人肉翻阅文档只能"看"，不能"问"

本项目正是针对上述痛点，构建一套本地化部署的校园资料智能检索系统：把校园文档统一托管、自动分类、语义检索，并基于RAG（检索增强生成）架构实现"带来源标注的智能问答"，全程使用本地开源模型，无需调用外部付费API，保障学生课件、培养方案等敏感校园数据不出校。

1.2 核心功能列表

  • 多格式文档上传：支持PDF、Word、TXT格式，自动提取文本内容并入库
  • AI自动文档分类：自动按校园场景归类，支持教师人工修正
  • 带溯源标注的智能问答：回答自动标注参考来源文档，防幻觉
  • SSE流式输出：回答以打字机效果逐字呈现，首字2-3秒可见，避免长时间空白等待
  • 三角色账号体系：学生（自行注册）/ 老师（管理员创建）/ 高级管理员（固定账号），密码加盐哈希加密存储
  • 问答历史留痕：每次提问自动保存，支持搜索、备注、修改权限
  • 三档内容权限：私有（仅自己可见）/ 仅链接可见（免登录分享）/ 公开（展示个人主页）
  • 分享链接与个人主页：生成分享链接，公开问答聚合展示在个人主页
  • 文档版本管理：同名文档自动保留历史版本，优先展示最新版，支持一键回滚
  • 教师文档管理：上传/删除/改分类/版本回滚归教师角色，按登录Token鉴权
  • 管理员后台：用户管理（新增/删除老师账号，删除时级联清理其文档与问答）、公开内容总管理
  • 教师评语：教师可对自己上传文档相关的公开问答写评语，学生历史/主页/分享页全端可见
  • 分类折叠展示：文档库按分类折叠，界面简洁清晰
  • 原文件查看：详情支持打开/下载原始文件，保留原始格式
  • 前端工程化：Vue3 + Pinia + VueRouter + Element Plus 多页面应用，路由级鉴权

2. 系统架构设计

2.1 总体架构

系统采用轻量前后端分离架构，无重型依赖，部署简单：

前端展示层：Vue3 多页面应用（学生 / 老师 / 高级管理员三套界面 + 公共登录注册页）
↓
后端服务层：FastAPI 提供RESTful接口，权限校验、业务逻辑
↓
数据层：SQLite 数据库（文档、分块向量、版本、用户、问答记录）
↓
模型层：
向量编码：BAAI/bge-small-zh-v1.5
大模型生成：Ollama 部署 Qwen2.5:3b

2.2 核心数据流程

入库链路：

用户上传文档 → 按类型提取文本(PDF/Word/TXT) → 按语义分块(每块约300字)
→ 向量编码(bge-small-zh) → 写入chunks表 → 调用大模型自动分类 → 写入documents表

问答链路：

用户提问 → 问题向量化 → 余弦相似度检索Top3文本块 → 相似度阈值判断(低分走正常对话)
→ 拼接上下文Prompt → 本地大模型流式生成(SSE逐字返回) → 前端打字机渲染 → 标注参考来源
→ 结束后自动存入问答历史

版本管理链路：

上传同名文档 → 检测同名最新版 → 弹出覆盖确认 → 旧版标记is_latest=0
→ 新文档version+1、parent_doc_id指向旧版 → 管理员可查看历史版本链并回滚

3. 数据库表结构设计

3.1 文档主表（documents）

字段名类型说明
id整数(主键)文档主键，自增
filename字符串用户上传的原始中文文件名
filetype字符串文件类型：pdf/word/txt
file_path字符串服务器存储的安全文件名路径（UUID命名防冲突）
content长文本提取后的文档全文内容
category字符串AI自动分类标签（培养方案/考试通知/课件资料/行政通知/社团文件/作业）
category_confirmed整数是否被管理员人工修正过（0=AI分类，1=人工修正）
version整数文档版本号，从v1开始递增
is_latest整数是否为当前最新版（1=最新，0=历史版），学生端仅展示最新版
parent_doc_id整数上一版本文档id，用于追溯历史版本链
uploaded_at时间文档上传时间

3.2 向量分块表（chunks）

字段名类型说明
id整数(主键)分块主键，自增
doc_id整数所属文档id，关联documents表
chunk_text长文本分块后的文本片段
embedding文本(JSON)文本片段对应的向量编码，用于相似度检索

3.3 关键设计说明

  • 版本链设计：通过 parent_doc_id 形成单向链表，配合 is_latest 标记实现"同名文档只展示最新版、可追溯历史版本链"的需求。为避免版本链循环引用（如parent指向自身），后端在回滚与查询时均增加了防循环遍历保护。
  • 向量存储：embedding字段以JSON字符串形式存储768维浮点向量，在轻量场景下避免了引入独立的向量数据库，降低部署复杂度。
  • 索引设计：对 is_latest、filename 字段建立查询索引，保证文档列表与同名检测的查询性能。

4. 核心模块实现

4.1 RAG检索与防幻觉模块（rag.py）

本模块负责文档分块、向量编码入库与相似度检索，是"能问答"的核心。

核心实现：

def search_top3_chunks(db_path: str, question: str) -> list:
    """问题向量化后与库中分块做余弦相似度匹配，返回Top3"""
    model = get_encoder()                      # 复用全局向量模型，避免重复加载
    q_vec = model.encode(question)             # 问题编码
    scored = []
    for chunk in all_chunks:                   # 遍历库中分块
        c_vec = json.loads(chunk["embedding"])
        sim = cosine_similarity(q_vec, c_vec)  # 余弦相似度
        scored.append((sim, chunk["text"], chunk["doc_id"]))
    scored.sort(reverse=True, key=lambda x: x[0])
    return [{"score": float(s), "text": t, "doc_id": d} for s, t, d in scored[:3]]
  • 文本分块：按每300字左右拆分，保留语义完整性
  • 相似度检索：余弦相似度匹配，返回最相关的3个文本块作为大模型上下文
  • 防幻觉机制：Prompt强制约束大模型只能基于检索到的片段回答，无相关内容时直接返回"找不到信息"，禁止编造内容
  • 闲聊识别：对检索相似度低于阈值的提问（如"你好"），自动切换为正常对话模式，避免无关文档被强行引用

4.2 本地大模型调用模块（llm.py）

通过OpenAI兼容协议调用Ollama本地部署的Qwen2.5:3B模型，实现回答生成、文档自动分类与SSE流式输出。

client = OpenAI(
    base_url="http://localhost:11434/v1",   # Ollama本地服务
    api_key="ollama",
    timeout=120.0,     # 本地CPU推理较慢，放宽超时
    max_retries=0      # 关闭自动重试，避免等待时间翻倍
)

def chat_stream(prompt: str):
    """流式生成：SSE逐块返回内容，首字2-3秒即可见"""
    response = client.chat.completions.create(
        model="qwen2.5:3b",
        messages=[{"role": "user", "content": prompt}],
        temperature=0.3,
        stream=True,               # 开启流式
        max_tokens=600,
        extra_body={"keep_alive": -1}   # 模型常驻内存，避免每次重新加载
    )
    for chunk in response:
        if chunk.choices[0].delta.content:
            yield chunk.choices[0].delta.content
  • 模型名与Ollama注册模型严格一致（qwen2.5:3b），通过 /api/tags 校验模型存在
  • 流式提速：stream=True 逐token返回，配合前端打字机渲染，闲聊首字约2.5秒、全程约4秒（原整段等待20秒+）
  • 模型常驻：keep_alive=-1 让模型常驻内存，避免每次提问重新加载；检索片段裁剪到300字/段，降低CPU prefill耗时
  • 异常兜底：大模型无响应时直接返回检索到的文档片段，页面不卡死

4.3 AI自动分类模块

文档上传后自动取前500字内容，调用本地大模型将文档分到6类校园场景：培养方案、考试通知、课件资料、行政通知、社团文件、作业。同时提供管理员人工修正接口，修正后的标注数据可用于后续模型持续微调。

    只返回分类名称。
    文档内容：{preview}
    分类结果："""
    # 优先精确匹配 → 同义词兜底（"实验/作业/用例"→作业，"课件/讲义/教案"→课件资料）→ 未分类
  • 分类提示词中明确"作业"与"课件资料"的边界定义，提升分类准确率
  • 增加同义词兜底匹配：模型回答不标准时也能正确归类，避免"未分类"堆积

4.4 权限与版本管理模块

  • 三角色权限：登录Token鉴权，学生/老师/高级管理员三角色隔离；文档管理归教师角色，私有问答任何角色不可见（详见第14章）
  • 版本管理：同名文档重复上传时，先查同名最新版（避免查到刚插入的自身），弹出覆盖确认后，旧版本标记is_latest=0，版本号递增，学生端仅展示最新版，管理员可查看完整历史版本链并一键回滚
# 上传时的版本升级核心逻辑（先查旧版，再保存新文档）
old = db.query(Document).filter(
    Document.filename == file.filename,
    Document.is_latest == 1
).first()
doc = save_document(db, file.filename, filetype, file_path, content)
if old:
    old.is_latest = 0            # 旧版转为历史版
    doc.version = old.version + 1
    doc.parent_doc_id = old.id   # 建立版本链

4.5 前端交互模块（Vue3工程）

Vue3多页面应用（frontend/），按角色组织界面：

  • 公共页：登录、注册（仅学生）、分享落地页、个人主页
  • 学生界面：AI问答（带参考来源标注）+ 文档库（分类折叠、搜索、排序、详情）+ 问答历史（备注/权限/分享）+ 个人主页 + 个人设置

  • 原文件查看：详情弹窗支持"打开原文件"，PDF直接预览、Word下载保留原格式

5. 后端接口设计

系统共提供20+个RESTful接口，均通过FastAPI实现，自带Swagger文档（/docs）。

POST/upload/ — 上传文档（教师，Bearer Token鉴权）

参数：file（文件）、confirm（同名覆盖确认标志）；鉴权：Authorization: Bearer <token>（教师角色）

流程：校验教师身份 → 校验格式(PDF/Word/TXT) → 检测同名 → 提取文本 → 保存入库（记录teacher_id归属）→ 分块向量化 → AI自动分类

返回：{msg, filename, version, category}

GET/documents/ — 文档列表（公开）

说明：返回所有最新版文档（is_latest=1），按上传时间倒序，学生端数据源

返回：[{id, filename, category, version}]

GET/documents/search/ — 按文件名搜索（公开）

参数：keyword（模糊匹配文件名）

返回：匹配的文档列表

GET/documents/{id} — 文档详情（公开）

说明：返回文档元数据与提取的全文内容，供详情弹窗展示

GET/file/{id} — 原文件查看/下载（公开）

说明：按类型返回原始文件（PDF直接预览、TXT直接显示、Word下载），保留原始格式

DELETE/documents/{id} — 删除文档（教师，Token鉴权）

鉴权：Bearer Token（教师角色）
说明：删除数据库记录并清理服务器上的原始文件

PUT/admin/documents/{id}/category — 人工修正分类（教师，Token鉴权）

参数：new_category
鉴权：Bearer Token（教师角色）
说明：教师手动调整AI分类结果，标记category_confirmed=1

GET/admin/documents/{id}/versions — 历史版本链（教师，Token鉴权）

说明：通过parent_doc_id递归遍历同一文件名的所有历史版本，支持一键回滚

POST/ask/ — RAG智能问答（登录用户，SSE流式输出，自动留痕）

参数：q（问题文本）；鉴权：Bearer Token（登录用户）

流程：问题向量化 → Top3检索 → 相似度阈值判断（低分走正常对话）→ 拼接Prompt → 本地大模型流式生成（SSE协议：data: {"c":"..."} 逐块 → data: {"sources":[...]} → data: [DONE]）→ 前端打字机渲染 → 结束后自动保存问答记录（默认私有）

POST/register/ — 学生注册

参数：username、password（≥4位）；角色固定为 student，用户名唯一校验，密码加盐SHA256存储

POST/login/ — 登录

参数：username、password；返回 token + role，token 写入 users 表，禁用账号拒绝登录

GET/me/ — 当前登录用户信息

鉴权：Bearer Token；返回 {user_id, username, role}

GET/qa/history/ — 我的问答历史

参数：keyword（可选，搜索问题/答案）；返回本人全部问答记录

PUT/qa/{id}/note — 写备注

说明：给本人问答记录添加备注，备注可见性跟随问答权限

PUT/qa/{id}/permission — 修改权限

参数：permission（private / link / public）；私有问答不允许生成分享链接

POST/qa/{id}/share — 生成分享链接

说明：返回分享token，供落地页 /qa/share/{token} 使用（免登录）

GET/qa/public/ — 问答广场（公开问答聚合浏览）

鉴权：Bearer Token（登录学生/教师均可）；联查 users 表按提问时间倒序返回全部公开问答，携带提问者用户名、备注、追加备注列表（qa_notes）与教师评语

POST/qa/{qa_id}/notes — 追加备注（多条追加，不覆盖）

鉴权：Bearer Token（登录学生）；参数：content（非空校验，前端限200字）

说明：仅可给公开问答追加备注；每次调用新增一条 qa_notes 记录，不覆盖旧备注；备注总量（旧note + qa_notes）达上限 QA_NOTES_LIMIT=10 时返回 400"该问答备注已达上限（10条）"

GET/users/{id}/profile 与 /users/{id}/qa_public — 个人主页

说明：免登录查看用户公开信息与其公开问答列表

POST/change_password/ — 修改密码

参数：old_password、new_password；校验原密码后重新加盐哈希存储

GET/teacher/qa/public/ — 教师查看学生公开问答

鉴权：Bearer Token（教师角色）；仅返回学生 role 的公开问答

PUT/teacher/qa/{qa_id}/note — 教师写评语

鉴权：Bearer Token（教师角色）；参数：note（评语内容，留空清除）

说明：仅可对自己上传文档关联的公开问答写评语（归属校验同删除接口）；评语与学生自己的备注（note）相互独立，展示在学生历史/个人主页/分享页

DELETE/qa/{id} — 教师删除关联公开问答

鉴权：Bearer Token（教师角色）；校验问答为公开权限且来源文档归属于该教师（teacher_id匹配）

GET/admin/users/ — 管理员查看全部用户

鉴权：Bearer Token（admin角色）；返回全部用户及账号状态

POST/admin/teachers/ — 管理员新增老师账号

鉴权：Bearer Token（admin角色）；创建 role=teacher 账号

DELETE/admin/users/{id} — 管理员删除账号

鉴权：Bearer Token（admin角色）；说明：直接删除账号并级联清理该用户上传的文档与该用户全部问答记录；不能删除自己、不能删除admin角色

GET/admin/qa/public/ 与 DELETE/admin/qa/{id} — 管理员公开内容总管理

鉴权：Bearer Token（admin角色）；查看/删除全部用户公开问答

6. 开发过程Bug记录与修复（AI协同核心证据）

本项目全程使用大模型辅助开发，以下记录真实开发过程中遇到的典型Bug与AI协同定位修复的过程，是"人机协同开发"能力的最直接证据。

Bug1：新开Git Bash窗口找不到uvicorn命令
现象：每次新开终端执行uvicorn都报 command not found
排查：uvicorn安装在项目虚拟环境(venv)中，新开终端未激活虚拟环境，Python包不在PATH中
修复：编写start.sh一键启动脚本，自动激活虚拟环境、配置HF镜像、启动服务，后续无需手动操作
经验：任何需要"每次手动重复"的环境操作都应脚本化，这也是项目可复现性的基础
Bug2：下载向量模型连接HuggingFace官网超时
现象：加载模型时报WinError10060连接失败，模型无法下载
排查：HuggingFace官网在国内网络环境下连接不稳定
修复：配置国内HF镜像端点 export HF_ENDPOINT=https://hf-mirror.com，模型下载速度从超时变为秒下
经验：国内环境使用开源模型必须考虑镜像加速，该配置已写入README复现指南
Bug3：新上传的文档学生列表看不到
现象：上传接口返回成功，但是前端文档列表不显示新文档
排查：学生端列表查询条件为 is_latest==1，而新文档保存时该字段未显式赋值，SQLAlchemy默认值为NULL，被过滤掉
修复：保存文档时显式设置 doc.is_latest = 1，上传后立即生效
经验：ORM字段默认值不可靠时，必须显式赋值，尤其是与查询条件强耦合的字段
Bug4：调用大模型时页面一直转圈无响应
现象：点击提问后前端长时间加载，最终无响应
排查：本地CPU推理较慢，且OpenAI SDK默认自动重试2次，30秒超时+2次重试导致总等待时间超过90秒
修复：超时放宽到120秒、关闭SDK自动重试(max_retries=0)、增加异常兜底直接返回检索片段
经验：本地推理场景必须按实际算力调整超时策略，不能沿用云端API默认配置
Bug5：前端跨域请求被浏览器拦截
现象：fetch调用后端接口报CORS错误
排查：前端以http://127.0.0.1:8000访问，后端未配置跨域许可
修复：在FastAPI中添加CORSMiddleware中间件，允许跨域访问
经验：前后端分离架构必须显式配置CORS，属于常见且必要的基础配置
Bug6：Ollama模型识别失败（404）
现象：问答返回"本地大模型暂时无响应"，日志显示chat/completions返回404 Not Found
排查：通过 /api/tags 查询发现模型列表为空。进一步排查发现：环境变量OLLAMA_MODELS指向D盘目录，而D盘只有下载中断的partial残片且缺少config/template/license/params等4个关联文件，模型库不完整
修复：从C盘旧模型目录复制完整模型（5个blob文件）到D盘目录，重启Ollama后 /api/tags 正常识别qwen2.5:3b
经验：Ollama模型库包含manifest注册文件与多个blob文件，任何一个缺失都会导致模型不被识别；模型迁移必须整体复制，不能只拷权重
Bug7：问答20秒+等待，演示录视频等不起
现象：每次提问要等20多秒才出结果，演示录屏8分钟根本录不完
排查：接口是"整段生成完再返回"；本地CPU推理慢，且Ollama模型每次调用后可能被卸载，二次提问要重新加载权重
修复：①/ask/改SSE流式输出，首字2-3秒就开始显示（打字机效果）；②keep_alive=-1让模型常驻内存；③检索片段裁剪到300字/段降低prefill耗时；④max_tokens限制单次回答长度。实测闲聊首字2.5秒/全程4秒，文档问答全程33秒降到7秒
经验：本地CPU推理场景，"流式输出+模型常驻+上下文裁剪"三件套是演示体验的关键
Bug8：权限迁移后教师管不了历史文档
现象：文档管理从admin迁移到教师后，教师删除/写评语全部返回403"只能管理自己上传的文档"
排查：documents表新增的teacher_id字段在迁移补列后全部为NULL，旧文档没有归属，归属校验全部失败
修复：将已有教学文档的teacher_id统一回填到teacher账号（UPDATE documents SET teacher_id=2 WHERE teacher_id IS NULL）
经验：表结构迁移补列时，存量数据的归属/外键字段必须一并回填，否则新校验逻辑会对旧数据"一票否决"
Bug9：前端美化后登录注册全部404
现象：界面重构+Vite代理改造后，登录注册接口全部404，页面无法使用
排查：vite代理规则使用带$锚定的正则（^/login/$），浏览器带query串的POST请求（/login/?username=..）不命中正则，被SPA回退消化
修复：代理规则全部改为字符串前缀写法（'/login/'、'/register/'、'/admin/users/'等），POST带query也能正确转发到后端
经验：Vite代理正则的$锚定会漏掉带query的POST请求，用字符串前缀匹配更稳妥；前端路由不带尾斜杠、后端API带尾斜杠可天然避免冲突

7. AI协同开发策略

本项目全程使用大模型辅助开发，核心Prompt设计思路：

  1. 小步迭代：一次只实现一个功能模块，跑通验证后再开发下一个，避免一次性生成大量代码出错
  2. 明确边界：每次需求都写清输入输出，避免AI生成多余代码
  3. 根因定位：遇到报错直接把终端堆栈信息反馈给AI，引导AI定位根因修复，不盲目改代码
  4. 可复现约束：要求AI写的代码无特殊环境依赖，所有依赖写入requirements.txt，环境变量单独配置
  5. 证据留痕：所有开发对话均保留完整记录（见Prompt证据链文档），每轮开发有明确的功能目标与验证方式
  6. 意图控制：给AI的Prompt全部包含"角色定义+任务边界+输出格式+禁止事项"四要素。例如文档分类Prompt明确"只返回分类名称"、问答Prompt明确"只能基于检索片段回答，无相关内容返回找不到信息，禁止编造"——从源头约束AI不瞎编
  7. 量化兜底：对AI输出做二次校验（相似度阈值0.45区分问答/闲聊、同义词兜底分类、来源文档标注），AI输出不可靠时用程序逻辑兜底，保证最终产物符合要求

10. 部署与运行说明

10.1 环境要求

项目要求
操作系统Windows 10/11（本项目开发环境）
Python3.10+（含venv虚拟环境）
大模型运行时Ollama（本地部署Qwen2.5:3B）
Node.js18+（前端Vue3工程构建/开发）
磁盘空间模型约1.9GB + 项目约300MB
网络首次安装需联网下载模型，运行时完全离线

10.2 启动与访问（前后端分离）

① 启动后端（FastAPI）：

cd backend
venv\Scripts\activate                 # Windows；Git Bash: source venv/Scripts/activate
export HF_ENDPOINT=https://hf-mirror.com
uvicorn main:app --host 0.0.0.0 --reload --port 8000

② 启动前端开发模式（Vue3，另一终端）：

cd frontend
npm install      # 首次运行安装依赖
npm run dev      # 访问 http://localhost:5173（已代理到8000后端）

③ 预设账号：高级管理员 admin / admin123；老师 teacher / teacher123；学生自行注册。

④ 局域网访问：后端绑定 0.0.0.0 后，同一WiFi下其他设备通过 http://本机IP:8000 或 http://本机IP:5173 访问。

⑤ 生产部署：前端 npm run build 生成 dist，由后端或静态服务器托管。

10.3 Ollama模型配置要点

  • 模型安装：ollama pull qwen2.5:3b（约1.9GB，支持国内镜像加速）
  • 模型目录：可通过环境变量OLLAMA_MODELS指定到非系统盘（如D:\ollama-models）
  • 模型迁移注意事项：必须整体复制manifests+blobs+metadata目录，任何文件缺失都会导致模型不被识别（见Bug6）
  • 识别校验：ollama list 或 GET /api/tags 确认模型可见

11. 可复现性论证

  • 所有依赖均为开源免费组件（FastAPI/SQLite/Ollama/Qwen/bge），无商业授权费用
  • 提供完整README复现指南，新环境10分钟即可跑通
  • 模型权重均为开源版本，支持国内镜像下载，无需特殊网络
  • 使用轻量SQLite数据库，无需额外部署数据库服务
  • 项目代码完整托管于GitHub/Gitee，支持一键克隆复现
复现步骤摘要：安装Python/Node/Ollama → 克隆项目 → ollama pull qwen2.5:3b → 后端 pip install -r requirements.txt 后 uvicorn main:app（8000）→ 前端 npm install 后 npm run dev（5173）→ 浏览器访问 localhost:5173 → 用 admin/teacher 预设账号或注册学生登录验证（完整命令见README）

12. 安全设计

  • 本地部署：全部组件（数据库、模型、服务）运行在本地，校园资料不出校门，从根源上避免云端泄露风险
  • 三角色鉴权：登录Token（Bearer）鉴权 + 后端角色依赖（get_current_user/teacher/admin）双校验，前端路由守卫防越权
  • 密码安全：随机盐+SHA256哈希存储，不存明文；修改密码需校验原密码
  • 私有内容隔离：私有问答与私有备注任何角色（含管理员）不可见，硬性规则在后端查询层强制
  • 越权防护：接口层按角色校验 + 前端路由守卫双层拦截，直接构造URL访问受保护页也无法通过
  • 文件名安全：上传文件以UUID重命名存储，原始文件名仅存数据库，防止路径穿越等注入攻击
  • 依赖安全：所有依赖锁定在requirements.txt，无高危漏洞版本

新增/删除老师账号✗✗✓

14.3 认证与加密

  • 密码加密：随机盐 + SHA256 哈希存储（格式 salt:digest），数据库不存明文
  • 登录态：登录返回 token（uuid），存 users 表，前端 Authorization: Bearer <token> 携带
  • 后端鉴权：get_current_user / get_current_teacher / get_current_admin 三个依赖，按接口角色校验
  • 前端路由守卫：未登录访问受保护页跳登录页；越权访问跳回本人角色首页；已登录访问登录页自动跳转
  • 预设账号：admin/admin123（高级管理员）、teacher/teacher123（老师），仅不存在时创建

15. 问答历史与三档权限分享

15.1 问答记录表（qa_records）

字段说明
user_id提问用户
question / answer问题与回答原文
sources / source_doc_ids引用来源文档（名称+ID），用于溯源与归属校验
permission三档权限：private（私有）/ link（仅链接）/ public（公开）
note用户备注（跟随问答权限可见性）
teacher_note教师评语（教师对自己文档关联的公开问答所写，与学生note相互独立）
share_token分享链接唯一标识（UUID）

15.2 三档权限机制

  • 私有：仅提问者本人可见，不出现在任何公开位置
  • 仅链接可见：任何人凭分享链接（/qa/share/token）免登录查看，不出现在个人主页
  • 公开：展示在提问者个人主页（/u/userId），任何人可访问
  • 硬性规则：私有问答与私有备注任何角色（含管理员）不可见

15.3 分享与主页流程

学生提问后自动留痕（默认私有）→ 在"问答历史"页可写备注、修改权限、生成分享链接 → 设为公开后自动出现在个人主页 → 他人通过分享链接或个人主页免登录浏览。

16. 教师文档管理与管理员后台

16.1 文档管理归属迁移

文档管理从"管理员密钥"模式迁移为教师角色 + 登录Token鉴权：上传接口记录文档归属（documents.teacher_id），删除/改分类/版本回滚接口均校验当前登录用户为老师角色。文档归属字段同时用于"教师删除关联公开问答"的校验。

16.2 教师删除关联公开问答

教师调用 DELETE /qa/{id} 时，后端校验：①问答必须为公开权限；②问答引用的来源文档（source_doc_ids）中至少一个属于该教师上传（documents.teacher_id == 教师ID），否则拒绝。保证教师只能清理自己文档产生的公开问答。

16.3 管理员后台能力

  • 查看全部用户（学生/老师/管理员）与账号状态
  • 新增老师账号（用户名+密码，校验唯一）
  • 删除账号（直接删除并级联清理该用户的文档与问答；不能删除自己与admin角色）
  • 查看/删除全部用户的公开问答与公开备注

16.4 教师评语机制

qa_records表新增teacher_note字段（教师评语），与学生自己的note备注相互独立：学生备注是自己的学习记录，教师评语是老师对公开问答的批改意见。教师通过 PUT /teacher/qa/{qa_id}/note 写入评语（归属校验：该问答引用的来源文档必须由该教师上传），评语随问答展示在学生端全部位置（问答历史、个人主页、分享落地页），形成"学生提问 → 教师点评"的教学闭环。

18. 问答广场与追加备注

18.1 问答广场（公开问答聚合浏览入口）

背景：早期版本中"公开"问答只展示在提问者个人主页（/u/userId），其他学生不知道主页链接就看不到他人的公开问答，知识共享链路断裂。为解决该问题，新增学生端问答广场页面，作为全校公开问答的聚合浏览入口。

  • 后端接口：GET /qa/public/（登录学生/教师均可访问），联查 qa_records 与 users 表，按提问时间倒序返回全部 permission=public 的问答，并携带提问者用户名、备注、追加备注列表与教师评语
  • 前端页面：PublicSquare.vue，学生导航新增"问答广场"菜单（/student/square）；每条问答展示提问者名字（可点击进入其个人主页 /u/:userId）、问答内容、教师评语与追加备注列表

18.2 追加备注机制（qa_notes 表）

设计原则：备注为追加式而非覆盖式——学生每次添加备注都新增一条记录，保留全部历史批注，不覆盖旧内容。新增 qa_notes 表存储追加备注：

字段说明
qa_id关联 qa_records.id（哪条问答）
user_id添加备注的学生（联查 users 表取用户名展示）
content备注内容（非空校验，前端 maxlength 200）
created_at添加时间（列表按时间正序展示）

18.3 防刷屏：备注条数上限

为避免单条问答备注过多，后端常量 QA_NOTES_LIMIT=10 限制备注总量：新增备注接口 POST /qa/{qa_id}/notes 会先统计该问答已有备注数（旧备注 note + 追加备注 qa_notes），达到 10 条后拒绝并返回 400"该问答备注已达上限（10条）"。经实测：连加 10 条全部成功，第 11 条被拦截。

18.4 教师删除兜底与级联清理

当某条公开问答的追加备注过多或内容不当，教师可直接整条删除该问答（DELETE /qa/{id}，仅限本人上传文档关联的公开问答），删除时级联清理其全部追加备注（qa_notes）；管理员删除任意公开问答同样级联清理。学生账号被删除时，其产生的全部问答及对应追加备注一并清理。经实测：教师删除问答后，该问答的 10 条备注在 qa_notes 表中全部消失。

18.5 备注展示位置

追加备注列表随问答同步展示在 7 个位置：问答广场、问答历史、个人主页、公开主页（/u/:userId）、分享落地页（/qa/share/:token）、教师公开内容管理、管理员公开内容总管理。每条备注显示添加者用户名、内容与时间，形成"学生提问 → 他人批注 → 教师点评/删除"的完整公开问答生态。
