校园资料AI检索助手 技术文档

1. 项目概述

本项目是面向校园场景的本地化智能资料检索系统，解决传统校园文档分散、查找困难、版本混乱的实际痛点。系统基于RAG（检索增强生成）架构，全程使用本地开源模型，无需调用外部付费API，保障学生课件、培养方案等敏感校园数据不出校。

核心功能列表

  • 多格式文档上传：支持PDF、Word、TXT格式，自动提取文本内容
  • AI自动文档分类：自动按校园场景归类，支持管理员人工修正
  • 带溯源标注的智能问答：回答自动标注参考来源文档，防幻觉
  • 两级权限隔离：学生可自由查询问答，管理员密钥才能上传/修改文档
  • 文档版本管理：同名文档自动保留历史版本，优先展示最新版

2. 系统架构设计

系统采用轻量前后端分离架构，无重型依赖，部署简单：

前端展示层：Bootstrap 单页界面（学生/管理员双视角）
↓
后端服务层：FastAPI 提供RESTful接口，权限校验、业务逻辑
↓
数据层：SQLite 数据库（文档元数据、分块向量、版本信息）
↓
模型层：
向量编码：BAAI/bge-small-zh-v1.5
大模型生成：Ollama 部署 Qwen2:1.5b

核心数据流程

用户上传文档 → 自动提取文本 → 按语义分块 → 向量编码入库
用户提问 → 问题向量化 → Top3相似度检索匹配 → 拼接上下文Prompt → 本地大模型生成回答 → 标注参考来源返回用户

3. 数据库表结构设计

3.1 文档主表（documents）

字段名类型说明
id整数文档主键，自增
filename字符串用户上传的原始中文文件名
filetype字符串文件类型：pdf/word/txt
file_path字符串服务器存储的安全文件名路径
content长文本提取后的文档全文内容
category字符串AI自动分类标签
category_confirmed整数是否被管理员人工修正过
version整数文档版本号，从v1开始递增
is_latest整数是否为当前最新版（学生仅看最新版）
parent_doc_id整数上一版本文档id，用于追溯历史版本链
uploaded_at时间文档上传时间

3.2 向量分块表（chunks）

字段名类型说明
id整数分块主键，自增
doc_id整数所属文档id，关联documents表
chunk_text长文本分块后的文本片段
embedding向量文本片段对应的向量编码，用于相似度检索

4. 核心模块实现

4.1 RAG检索与防幻觉模块

  • 文本分块：按每300字左右拆分，保留语义完整性
  • 相似度检索：余弦相似度匹配，返回最相关的3个文本块作为大模型上下文
  • 防幻觉机制：Prompt强制约束大模型只能基于检索到的片段回答，无相关内容时直接返回"找不到信息"，禁止编造内容

4.2 AI自动分类模块

文档上传后自动取前500字内容，调用本地大模型将文档分到5类校园场景：培养方案、考试通知、课件资料、行政通知、社团文件。同时提供管理员人工修正接口，修正后的标注数据可用于后续模型持续微调。

4.3 权限与版本管理模块

  • 两级权限：学生无需登录即可查询、问答；管理员密钥校验后才能上传、删除、修改文档
  • 版本管理：同名文档重复上传时，自动将旧版本标记为历史版，版本号递增，学生端仅展示最新版，管理员可查看完整历史版本链

6. 开发过程Bug记录与修复（AI协同核心证据）

Bug1：新开Git Bash窗口找不到uvicorn命令
现象：每次新开终端执行uvicorn都报command not found
修复：编写start.sh一键启动脚本，自动激活虚拟环境、配置镜像、启动服务
Bug2：下载向量模型连接HuggingFace官网超时
现象：加载模型时报WinError10060连接失败
修复：配置国内HF镜像端点，export HF_ENDPOINT=https://hf-mirror.com，模型下载速度从超时变为秒下
Bug3：新上传的文档学生列表看不到
现象：上传接口返回成功，但是前端文档列表不显示新文档
修复：排查发现新文档的is_latest字段未显式赋值为1，被学生端列表过滤，修复后正常显示
Bug4：调用大模型时页面一直转圈无响应
现象：点击提问后前端加载无响应
修复：在llm.py中加30秒超时设置和异常兜底，大模型无响应时直接返回检索到的文档片段，不卡页面
Bug5：前端跨域请求被浏览器拦截
现象：fetch调用后端接口报CORS错误
修复：在FastAPI中添加CORSMiddleware中间件，允许跨域访问
Bug6：Ollama模型拉取失败
现象：ollama pull命令报manifest file does not exist
修复：核对正确的模型仓库名qwen2:1.5b，成功拉取934MB模型权重

7. AI协同开发策略

本项目全程使用大模型辅助开发，核心Prompt设计思路：

  1. 小步迭代：一次只实现一个功能模块，跑通验证后再开发下一个，避免一次性生成大量代码出错
  2. 明确边界：每次需求都写清输入输出，避免AI生成多余代码
  3. 根因定位：遇到报错直接把终端堆栈信息反馈给AI，引导AI定位根因修复，不盲目改代码
  4. 可复现约束：要求AI写的代码无特殊环境依赖，所有依赖写入requirements.txt，环境变量单独配置
